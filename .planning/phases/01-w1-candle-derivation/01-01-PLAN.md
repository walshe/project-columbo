<objective>
Extend both the PostgreSQL `timeframe` enum and the Java `Timeframe` enum so that `W1`
is a first-class, type-safe timeframe value throughout the system.

Purpose: Every downstream concern in this phase (rollup service, persistence, future
indicator passes) depends on `W1` existing in BOTH the database enum and the Java enum.
The PostgreSQL enum and Java enum are decoupled — adding to only one causes runtime
deserialization failures. This plan is the foundation; nothing else in the phase can
function without it.

Output: Flyway migration `V13__add_w1_timeframe.sql`, an updated `Timeframe` enum with
the `W1("1W")` constant, and a unit test confirming `Timeframe` round-trips `W1`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Flyway migration → live database schema | DDL statement (`ALTER TYPE`) mutates a shared production type at application startup |
| Java enum ↔ PostgreSQL enum | Two independently-maintained representations of the same domain value must stay in sync |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | V13 migration file | mitigate | `ALTER TYPE ... ADD VALUE IF NOT EXISTS` is additive and idempotent — cannot drop or alter existing `D1` rows; no data mutation |
| T-01-02 | Denial of Service | Application startup | mitigate | Migration is a single fast DDL with `IF NOT EXISTS`; mirrors proven V8; no long-running lock on the `candle` table |
| T-01-03 | Repudiation | Schema change tracking | accept | Flyway records V13 in `flyway_schema_history` with checksum and timestamp — standard, sufficient audit trail |
| T-01-04 | Information Disclosure | Migration content | accept | Migration contains no secrets, credentials, or PII — pure DDL |
| T-01-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this plan — `flyway-database-postgresql` and all deps already in pom.xml (RESEARCH.md "installs zero external dependencies") |

No new HTTP endpoint, authentication surface, or user input is introduced. ASVS L1
categories V2–V6 do not apply (RESEARCH.md Security Domain).
</threat_model>
