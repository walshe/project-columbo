<objective>
Add an optional per-condition `timeframe` field to `ScanCondition` and make the top-level `ScanRequest.timeframe` optional (nullable). These are the input-DTO half of the multi-timeframe scan: each condition can now declare which timeframe it targets instead of inheriting a single global timeframe from the request.

This plan modifies only the two input DTO records. It does NOT touch the service, validator, response DTOs, or tests — those follow in plans 04-02 and 04-03. After this plan, main sources compile cleanly; test compilation may be broken (tests construct `ScanCondition` with positional args) and is fixed in plan 04-03.

Purpose: SCAN-01 (`ScanCondition` gains optional `timeframe`), SCAN-02 (`ScanRequest.timeframe` becomes optional), SCAN-04 (backward compatibility preserved — existing clients sending `ScanRequest.timeframe` with conditions that carry no per-condition `timeframe` continue to work).
Output: Modified `ScanCondition.java` and `ScanRequest.java`.
</objective>
