## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scheduler/HTTP trigger → MarketPipelineService.runDaily() | Pipeline entry point; trigger payload (provider/timeframe) is bounded by enum types — no free-form input |
| MarketPipelineService → DB (rollup + W1 writes) | Bulk W1 candle/indicator/signal/breadth writes within a transaction |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Denial of Service | W1 phases appended to runDaily() lengthen pipeline duration | accept | W1 pass operates on the same active-asset set already processed for D1; rollup + indicators are bounded linear work. Daily pipeline is not latency-sensitive (cron-driven). No external calls added. |
| T-03-02 | Tampering | A W1-phase exception aborting the run after D1 work committed | mitigate | W1 phases run inside the existing try block; the existing `catch`/`finalizeRun` records the run as FAILED without rolling back already-committed D1 phase work (each underlying service is independently `@Transactional`). Test `shouldMarkRunAsFailedOnException` confirms failure handling stays intact. |
| T-03-03 | Repudiation | W1 processing not auditable in run history | mitigate | Per-phase log-before/log-after-with-duration for W1_ROLLUP and W1_PROCESSING; IngestionRun status reflects whole-run outcome including W1 (PIPE-03). |

No new HTTP endpoints, auth paths, package installs, or external network calls introduced — `T-{phase}-SC` not applicable (no package-manager installs in this plan).
